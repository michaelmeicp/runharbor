# Specification amendments — 2026-09-26

The product owner authorized aligning the specification to the existing implementation. Requirement IDs and outstanding acceptance tests remain unchanged. The original private brief is not published; its revised full copy is kept outside this Git repository. This public amendment is the repository's normative record of those decisions.

| Specification section   | Adopted decision                                                                                                                                                                                                                                                                                                                                 |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Naming, paths, branches | RunHarbor; `runharbor`; default `~/.runharbor`; `runharbor.db`; future branches `runharbor/<slug>`. The package scope remains `@michaelmeicp/runharbor`.                                                                                                                                                                                         |
| §9.1–9.2                | JavaScript ES modules, Node `http`, native DOM/CSS, `node:sqlite`, scrypt (N=32768, r=8, p=1). No TypeScript rewrite is currently scheduled. Runtime checks remain required.                                                                                                                                                                     |
| §9.3                    | Flat `src/`, `web/`, `tests/`, `scripts/`, `packages/adapter-sdk/`, `fixtures/`, `docs/`; user data outside the repository.                                                                                                                                                                                                                      |
| §4.3                    | Domain entities use the generic JSON `entities` table; settings/events/audit/search have dedicated tables. This is a physical-model change, not removal of domain requirements or a performance claim.                                                                                                                                           |
| Schema evolution        | Ordered, transactional migrations with a checksum ledger. Legacy v1 upgrades to v2 without deleting entities or settings. Failed migrations roll back; unknown versions and altered history are rejected. Back up the stopped data directory before upgrades; encrypted automated backups remain unfinished.                                     |
| §11                     | On 2026-09-25 the owner authorized skipping M0 before the mock M1–M4 slice and publishing alpha. This is an execution-order/preview exception; M0, G4 and the 19-item v1 gate are not passed.                                                                                                                                                    |
| §7.2, §7.4, §9.1        | Codex argv requires an explicit absolute worktree and JSON output schema. Claude T0 explicitly denies Bash/Edit/Write; T1 denies Bash. Use the specification's literal `--setting-sources user` plus generated `--settings`, disabled hooks and strict empty MCP configuration. Live execution is still blocked pending installed-version tests. |

The schema does not yet enforce every domain relation at SQL level. The 50,000-run target, full sandbox proof, live session continuation, and production distribution remain open. See [implementation status](implementation-status.md).

CLI references: [official Codex commands](https://learn.chatgpt.com/docs/developer-commands?surface=cli) and [Claude CLI](https://code.claude.com/docs/en/cli-reference). Local Codex 0.157.0 help confirms `-C` and `--output-schema`; Claude runtime behavior still requires an installed authenticated CLI. Choosing `user` avoids claiming the previous empty-source form was verified.
